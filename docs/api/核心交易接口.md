# 核心交易接口契约（v1）

> 维护：A（后端负责人）
> 适用范围：订单、支付、库存、售后
> 约定：所有接口返回统一 `Result<T>`；金额单位为**分**；时间为 `yyyy-MM-dd HH:mm:ss`（Asia/Shanghai）。

## 1. 通用请求头

| 请求头 | 必填 | 说明 |
| --- | --- | --- |
| `Authorization` | 除公开接口外必填 | `Bearer <token>`，Token 存 Redis（方案 B） |
| `Idempotency-Key` | 关键写接口必填 | 客户端生成 UUID；服务端按 `(user_id, biz_type, idem_key)` 去重 |
| `X-Trace-Id` | 否 | 不传则服务端生成，响应头与 `Result.traceId` 返回 |

## 2. 统一返回

```json
{
  "code": 0,
  "message": "OK",
  "data": {},
  "traceId": "9953b5f18fe646be8b32a06b2c6f3f0f",
  "timestamp": 1792378874909
}
```

`code=0` 成功；失败见错误码。

## 3. 订单接口

### 3.1 提交订单（已实现）

```http
POST /api/v1/orders
Authorization: Bearer <token>
Idempotency-Key: <uuid>
Content-Type: application/json
```

请求体：

```json
{
  "addressId": null,
  "fulfillType": 2,
  "couponId": null,
  "remark": "少放辣",
  "items": [
    { "productId": 1, "quantity": 2 }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| addressId | long | 配送必填 | 收货地址 ID；自提为空 |
| fulfillType | int | 是 | 1 配送、2 自提 |
| couponId | long | 否 | 用户优惠券 ID（本期先保留） |
| remark | string | 否 | 最长 255 |
| items[].productId | long | 是 | 商品 ID |
| items[].quantity | int | 是 | 数量 ≥ 1 |

成功响应：

```json
{
  "code": 0,
  "message": "OK",
  "data": { "orderNo": "ORD20261019111321000123", "payAmount": 2580, "status": "PENDING_PAYMENT" },
  "traceId": "…",
  "timestamp": 1792378874909
}
```

**处理语义**：
1. 校验 `Idempotency-Key`；
2. 首次请求：锁定库存 → 创建订单/订单项 → 回写幂等记录（同一本地事务）；
3. 重复请求：若已完成，返回首次订单；若处理中，返回 `30004`；
4. 任一商品不存在/下架 → `20002`；库存不足 → `20003`；
5. 失败整体回滚，不产生「锁了库存没订单」。

### 3.2 订单列表

```http
GET /api/v1/orders?status=0&pageNum=1&pageSize=10
Authorization: Bearer <token>
```

返回 `PageResult<OrderVO>`（待实现）。

### 3.3 订单详情

```http
GET /api/v1/orders/{orderNo}
Authorization: Bearer <token>
```

### 3.4 取消订单

```http
POST /api/v1/orders/{orderNo}/cancel
Authorization: Bearer <token>
Idempotency-Key: <uuid>
```

语义：仅「待支付」可取消；条件更新订单状态 → 释放库存 → 退回优惠券（后两者同事务）。重复取消返回 `30002` 或幂等成功。

### 3.5 确认收货

```http
POST /api/v1/orders/{orderNo}/confirm
Authorization: Bearer <token>
Idempotency-Key: <uuid>
```

语义：仅「待收货」可确认；状态迁移到「已完成」。

### 3.6 到店自提核销

```http
POST /api/v1/orders/{orderNo}/pickup
Authorization: Bearer <token>
Idempotency-Key: <uuid>
```

语义：「待收货（自提备货完成）」→「已完成」。

## 4. 支付接口

### 4.1 发起支付

```http
POST /api/v1/payments
Authorization: Bearer <token>
Idempotency-Key: <uuid>
Content-Type: application/json
```

```json
{ "orderNo": "ORD20261019111321000123", "channel": 1 }
```

响应：`{ "payNo": "...", "status": "PENDING_PAYMENT" }`（沙箱参数后续按需扩展）。

> 支付状态同样使用字符串枚举：`PENDING_PAYMENT / PAYING / PAID / FAILED / CLOSED`。轮询 `GET /payments/{payNo}` 成功时返回 `status: "PAID"`。

### 4.2 支付结果查询

```http
GET /api/v1/payments/{payNo}
Authorization: Bearer <token>
```

### 4.3 支付回调（沙箱）

```http
POST /api/v1/payments/callback
Content-Type: application/json
```

```json
{ "payNo": "...", "tradeNo": "...", "amount": 2580, "sign": "..." }
```

语义：
1. 验签、校验金额与订单号；
2. 以 `pay_no` 幂等；
3. 订单「待支付」→「待发货」，库存 `locked → sold`；
4. 若订单已关闭（支付 vs 关单竞态）→ 创建退款单并发起沙箱退款，不复活订单。

## 5. 售后接口

### 5.1 申请售后

```http
POST /api/v1/after-sales
Authorization: Bearer <token>
Idempotency-Key: <uuid>
```

```json
{ "orderNo": "...", "type": 1, "reason": "水果不新鲜", "amount": 1290 }
```

### 5.2 售后列表 / 详情

```http
GET /api/v1/after-sales
GET /api/v1/after-sales/{saleNo}
Authorization: Bearer <token>
```

### 5.3 售后审核（运营）

```http
POST /api/v1/admin/after-sales/{saleNo}/audit
Authorization: Bearer <token>
Idempotency-Key: <uuid>
```

```json
{ "approved": true, "remark": "同意退款" }
```

语义：同步发起沙箱退款；成功即回写「已完成 / 已退款」；超时或失败置「退款中」，由定时任务对账补偿。

## 6. 内部服务契约（供 B 的售后模块使用）

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `OrderQueryService` | `getByOrderNo(orderNo, userId)` | 查订单并校验归属；不存在/无权抛 `99001` |
| `OrderStateMachine` | `transition(orderNo, from, to)` | 按合法流转表迁移；非法/并发失败抛 `30002` |
| `InventoryService` | `lock / deduct / release` | 三态库存原子操作 |
| `PaymentRefundService`（规划） | `refund(orderNo, amount, afterSaleId)` | 沙箱退款；按 `refund_no` 幂等 |

> 售后模块只调用以上接口，不直接写 `t_order`、`t_payment`。

## 7. 订单状态与合法流转

| 当前 | 可流转到 |
| --- | --- |
| 0 待支付 | 1 待发货、4 已取消 |
| 1 待发货 | 2 待收货、5 售后中 |
| 2 待收货 | 3 已完成、5 售后中 |
| 3 已完成 | 5 售后中 |
| 5 售后中 | 6 已退款、回退至申请前状态 |
| 4 已取消 / 6 已退款 | 终态 |

## 8. 错误码（核心交易）

| 码 | 含义 |
| --- | --- |
| 10002 | 未登录或登录失效 |
| 10003 | 无操作权限 |
| 20002 | 商品不存在或已下架 |
| 20003 | 库存不足 |
| 30002 | 订单状态不允许该操作 |
| 30004 | 重复请求（幂等处理中） |
| 30005 | 订单已关闭 |
| 99001 | 资源不存在或无权访问 |
| 90001 | 系统异常 |

## 9. 变更规则

- 本文件为前后端唯一契约；字段变更先改本文档，再改代码。
- 新增接口需同步需求文档 6.1、设计文档 8.6 与 OpenAPI。
- 关键写接口必须携带 `Idempotency-Key`。
